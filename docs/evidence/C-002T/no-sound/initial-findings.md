# 无声调查：代码侧第一批证据

仅代码/离线调查，未启动App/监听/硬件声音，未操作UI/系统设置；主对话负责GUI复现。

## 可用现有诊断入口（由主对话操作）

新版：启动卡“开始打字钢琴”或♪菜单“开始打字钢琴”一起启用持续全局输入+声音+画面。需要该新版身份已有输入监控授权；失败将完整停止，启动卡给真实错误。

隔离输入权限：测试子菜单→打开测试控制台→本窗口测试60秒→启用所选声音→点击控制台钢琴中的字母A/C等白键（全64音库或合成测试源）。旧C001C相同控制台流程；旧/测试60秒启动自身不启声，且每次重新启动测试会先pause关闭已有音频。声开后不要再按一次测试启动，否则会再次关闭声音。

控制台内存“有效事件N/当前按住”可分辨输入有无送达；菜单声音勾选和“关闭声音并清尾音”按钮文字代表已prepare，但不能证明硬件声学输出。当前没有输出RMS/设备诊断CLI；--self-check与--menu-smoke不播放声音，不能当声卡测试。

## 源码确认与尚未确认

1. Code/Sources/PianoMac/ProbeController.swift start(global:)会pause→resume→input.start，未audio.enable；这是测试观察路径，不是新版主开始动作。toggleSound明确单独启声。
2. startTrial()先input.start再audio.enable；任一抛错都会pause清理。观察控制台/启动卡原始错误比继续调音量更有区分力。
3. receive收到事件后只在coordinator.soundEnabled且audio.enabled时发noteOn；0滑块和缺音候选也有意无声。新默认完整Steinway不缺音；旧候选仅10/11音，若选择它们，未覆盖琴键无声是预期。
4. installSafetyHooks监听全部AVAudioEngineConfigurationChange对象，只要audio.enabled便全局pause；没有引擎身份/代次过滤。旧引擎延迟通知可能误停新音频，是源码确认的通知隔离缺口；尚无本次硬件触发证据。若状态出现“音频配置变化：已停用”，可优先定位此路径。
5. 新版61项测试证明离线音库、增益及mock控制器，未证明实时设备输出。不能用离线通过排除实际输出链路问题，也不应无证据继续增益。
