# CR-004 原生Dock联动、自适应宽度和紧凑菜单栏

日期：2026-10-28。依据用户在实际0.2.1试用中的反馈，优先于旧热区/固定宽度建议。

## 确认的体验

- 菜单栏保持单个♪，占位收窄。旧Reviewed-C001C与新试用版并存导致两个图标，主已通过活动监视器正常退出旧PID43519。
- 使用macOS系统原生“自动隐藏和显示程序坞”，默认开启；鼠标触发系统Dock显示的行为交给macOS，不由App模拟或拦截。
- 主对话已按用户明确要求，在系统设置将该开关从off改为on，UI与defaults均确认。此后App以用户现有true为基线，不能用旧false恢复覆盖用户刚选的设置。
- 钢琴根据Dock**实际显示**缓慢淡出，Dock实际隐藏后缓慢淡入；不能仅靠鼠标靠近底边的大热区推断。隐藏只影响视觉，不停听音或丢失按键/尾音状态；不重播隐藏期间的历史音符。
- 关闭系统Dock自动隐藏仍需告知会与钢琴冲突，并允许取消。
- 钢琴自动适应当前屏幕宽度，日常无需选择900/1000/1100pt；建议左右8pt小留白，64键/音高/标签保持一致。当前屏幕1512×982pt。
- 保持用户已确认输入监控和正常发声；本轮新构建先独立候选，当前0.2.1不覆盖直至审核。新签名若使TCC失效，按可见授权流程处理，不绕过系统权限。

## 实现与验证

C：实际原生Dock设置、真实可见性探针、渐隐渐显状态机、自动宽度、紧凑图标和同App实例防重；不把未知状态当已确认的隐藏。U：适配与动效参数/参考数据，不另建App。

主现场证据位于docs/evidence/PM-004-dock-adaptive。第一次用户操作未同期采样，不作成功证据；第二次同期600样本捕捉到Dock窗口49/layer20由hidden→visible→hidden，bounds始终整屏，故以实际onScreenOnly成员关系观察。0.2.4已安装：原生开关即时生效，实际App浮层淡出/淡入及1496pt自适应宽度通过，菜单实际槽宽20pt，音频引擎持续运行。详见reviews/PM-004.md。新开发签名需用户重新确认输入监控；未把旧版授权或CLI权限外推为新版GUI已授权。
