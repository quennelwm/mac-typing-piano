# CR-010：紧凑菜单与输入监控入口

用户直接要求主菜单宽度约减半、内容美观整理、输入监控授权加入主菜单，点击♪打开/再次点击关闭、菜单外点击关闭。PM-033批准按现有原生NSMenu增量实现，0.2.10/build13；不另造复杂窗口。

## 布局
主菜单目标约180pt（允许170—195pt系统布局差异），以同环境0.2.9实际NSMenu测量对比，不能把view宽度当最终菜单宽度。保持系统字体和原生材质。三滑块各自两行：标题左/百分比右，滑条下一行，标题及100%/180%不裁切；常用音量、高度、透明度留在根菜单，范围和保存语义不变。主菜单按运行、声音、外观、设置/帮助分组；简短状态，详述移至tooltip/子菜单。

建议根顺序：运行状态、开始/暂停；声音开关、音量；显示钢琴、按键标签、高度、透明度、自定义键位；输入监控授权…、系统选项、帮助与测试；退出。启动窗口、下载、测试放帮助子菜单；系统提示音及Dock操作/状态放系统子菜单；自动适配屏幕这类静态说明移至帮助，避免日常菜单冗长。状态错误不能隐藏，根用“设置未保存”“减少透明度已启用”等短句，全文有可访问入口或tooltip。任意状态不将根菜单重新撑宽。

## 权限入口
主菜单直接可见“输入监控授权…”。打开菜单只读预检并显示实际状态，不能申请权限或改变运行。点击时未授权复用现有显式授权流程（可显示现有说明小窗）；已授权只打开系统输入监控页，不停声音、不重置TCC、不重新发起授权。失效/取消/安全输入仍按既有保护处理。不得扩大权限范围。

## 显隐
优先保留NSStatusItem.menu与NSMenu系统跟踪；不要用常驻面板或全局鼠标拦截模拟菜单。确认♪首次点击展开、同图标再次点击收起、外部点击收起；滑块拖动不误关闭，关闭时偏好继续补存，子菜单不触发重复保存或意外重启。

## 验收
0.2.9/新菜单同环境最终逻辑宽度与根条目数量对照；正常/未授权/已授权/安全输入/保存失败/减少透明度等状态无撑宽/裁切。滑块原生target-action、持久化、权限入口分支测试；源冻结完整回归一次。提供紧凑菜单可视预览或真实菜单截图（注明方式）和可复查尺寸证据。实机点击开关/外部关闭与模拟逻辑分开记录。既有高度/透明度/音量/映射及声音状态保留。沿用固定签名、Bundle ID和安装路径；候选不启动GUI、不覆盖正式安装，由主验收后安装发布。
