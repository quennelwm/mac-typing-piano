## 01｜项目背景与用户目标

### 1.1 起点与产品定位

用户希望在 MacBook 上正常处理微信、文档、网页、代码等日常工作时，键盘输入能像触碰钢琴一样产生声音与视觉反馈。它不是需要获得焦点后才能弹奏的钢琴 App，也不是为了练琴、识谱、录歌而设计的数字乐器。

理想体验是：工作方式完全不变；打字同时出现柔和钢琴声；屏幕底部一条轻量钢琴跟随按键下沉和回弹；需要操作系统 Dock 时，钢琴自动让位；不需要时又回到桌面。软件可以长期开着，但不会成为新的工作负担。

早期讨论曾比较 32、61、88 键。最终范围明确为 MacBook 内置键盘下方五排，排除整个最上方 Esc／功能键／Touch ID／电源区域。本版以 ANSI 布局的 **64 个实体键** 为输入设计基准，屏幕采用相应的 64 个连续钢琴音位。

### 1.2 用户真正想要的结果

| 目标 | 具体含义 | 不可被替代成 |
|---|---|---|
| 自然伴随工作 | 在其他 App 正常输入即可触发 | 必须点击钢琴窗口才能响 |
| 全键参与 | 字母、数字、标点、Shift、Command、Option、空格等均参与 | 擅自静音修饰键或把空格强制改成踏板 |
| 多音与延音 | 多个按键可同时响，松开后有自然尾音 | 单声道逐键覆盖，或松开立即截断 |
| 看得见回应 | 对应琴键独立下沉、保持、回弹 | 一张全键盘图片整体闪烁 |
| 小屏可用 | 优先 13、14 英寸，兼顾 16 英寸 | 只在大显示器的效果图上好看 |
| 明确的按键提示 | 标签可开关，默认每个黑白琴键底部有灰色小标签 | 开启时只在设置页显示，或按下后才显示 |
| Dock 优先 | 用户操作 Dock 时立即让位 | 改造、注入、遮住系统 Dock |

### 1.3 成功标准

用户可以连续工作至少一小时，不需要反复切换到本软件；输入法、快捷键和 Dock 操作不受破坏；声音不越积越响；琴键不会卡住；界面没有焦点抢占；所有未支持的系统行为都有明确说明。

“任意打字都自动形成好听的旋律”不属于本版承诺。固定音高映射保留输入与琴键的一致性，听感通过音色、音区、音量和尾音打磨，而不是偷偷替换用户刚敲下的音。

### 1.4 首版不做

不做乐谱、教学、曲库、录制、MIDI 导出、AI 作曲、账号、云同步、广告、社交、Windows／iOS 版本或复杂主界面；不注入/重绘系统 Dock，只按用户选择控制其自动隐藏；不安装驱动，不绕过安全输入，不采集输入文字。商品名称、收费与上架渠道另行讨论，不阻塞原型。

## 03｜按键数量、布局与映射

### 3.1 下方五排清单

| 物理排 | 内容 | 数量 |
|---|---|---:|
| 数字排 | 反引号、1—0、减号、等号、Delete | 14 |
| Q 排 | Tab、QWERTYUIOP、左右方括号、反斜杠 | 14 |
| A 排 | Caps Lock、ASDFGHJKL、分号、单引号、Return | 13 |
| Z 排 | 左 Shift、ZXCVBNM、逗号、句点、斜杠、右 Shift | 12 |
| 底排 | Fn、Control、左右 Option、左右 Command、空格、四个方向键 | 11 |
| 合计 | 左右键分别计数，方向键为四个实体键 | **64** |

64 是设计输入清单，不是对任何 macOS 版本都可捕获 64 个独立按下／松开事件的保证。尤其 Fn、Caps Lock 必须用 V-01 实测记录说明；不能凭画了 64 键就宣布全键支持。

### 3.2 屏幕钢琴

采用十二平均律的连续 MIDI 音位 33—96，共 64 个。按本项目约定中央 C 为 C4＝60，因此边界为 A1—C7；对应 38 白键、26 黑键。所有资源以 **MIDI 整数** 为主键，音名只用于说明，避免不同音源的八度命名差异。

屏幕是一条正常钢琴，不是五排电脑键盘。黑键按真实的两枚／三枚规律排列，E—F 与 B—C 之间不添加黑键。首尾不额外画超出范围的半个琴键。

### 3.3 黑白分组

白键对应 26 个字母、字母区域八个标点、左右 Shift、Return、Space，共 38 个。黑键对应整个数字排十四键、底排除空格外十键、Tab、Caps Lock，共 26 个。

机器可读初稿位于 `contracts/keymap.ansi64.v0.1.json`，逐键表位于 `docs/05_Keymap_Reference.md`。初稿覆盖全部 64 个音位并固定标签，用于并行联调；**它不是已经通过用户试听的最终音乐映射**。主对话在 M2 试听后决定是否调整。

为避免三条工作线各排各的琴键，音效按 MIDI 编号交付，UI 从映射表读取实体键标签，代码从同一份映射表触发音符。不得在贴图、Swift 源码和音频文件名中分别维护三份不同的对应关系。

### 3.4 事件规则

- 一个物理按下事件只产生一次击发；系统自动重复不重新击发，松开后再按才重击。
- Shift＋A 产生两个音，A 的音高不变；中文拼音逐个物理键响应，不等待汉字上屏。
- Command 按住期间多次 C、V，各字母正常击发，Command 只在最初按下时击发。
- 左右 Shift／Command／Option 独立；不能只用“某类修饰键是否按下”的总标志推断两侧状态。
- Caps Lock 的锁定状态不等于手指持续按住。仅能可靠收到状态切换时，使用可解释的短脉冲动画／声音，不伪造持续按压。
- Fn 事件缺失时，不用随机事件补齐；保留音位及 `fn` 标签，在设置中显示识别限制并报主对话处理。
- 映射切换前统一释放旧音和按键状态，不允许旧版本 note-off 影响新版本。

## 04｜典型流程与产品状态

### 4.1 首次启动

先展示本 App 内可试用的钢琴和权限说明；用户主动打开“全局打字反馈”后，再申请输入监控。拒绝授权时保留本地预览，不循环弹窗。授权检测成功且监听器实际工作后，才显示“全局已开启”。重启是否必要以实测提示为准，不伪造已授权。

### 4.2 日常使用

用户在其他 App 输入，监听器只观察；统一按键状态驱动音频和琴键。鼠标靠近底部，浮层让位；声音继续。鼠标离开并经过恢复延时，浮层重现当前状态，不回放隐藏期间的动画。

### 4.3 开关语义

| 状态 | 输入监听 | 声音 | 浮层 |
|---|---|---|---|
| 正常开启 | 开 | 按用户设置 | 按场景显示 |
| Dock 避让 | 开 | 不受影响 | 隐藏 |
| 仅声音 | 开 | 开 | 关闭 |
| 仅动画 | 开 | 关闭，停止已有尾音 | 开 |
| 声音与动画都关 | 可停止并提示 | 关 | 关 |
| 暂停全部 | 停止 | 全部停止并清空尾音 | 隐藏 |
| 锁屏／睡眠／权限失效 | 安全暂停 | 全部停止 | 隐藏 |
| 排除应用／安全输入 | 不产生反馈，清理状态 | 停止 | 隐藏或明确停用 |

恢复时不根据不可靠历史猜“哪些键仍按着”。从空状态重新观察可靠的新事件；不能把旧的 Command 长鸣带到下一次会话。

### 4.4 设置与菜单栏

菜单栏图标点击展开/收起原生下拉菜单，保留暂停／恢复、声音开关与音量、显示钢琴、显示按键标签、自动隐藏Dock、少量外观/行为子菜单、帮助/关于与退出。不做复杂主窗口或四页设置中心；授权说明、试听与映射预览按需打开小窗口。

显示标签默认开启、可关闭并保存，只控制独立文字层。自动隐藏Dock默认开启，控制系统Dock自身设置；关闭前提示“关闭自动隐藏后，Dock 可能与底部钢琴重叠或遮挡。仍要关闭吗？”，提供“保持自动隐藏”和“仍然关闭”。取消不改值，确认才关闭；失败不能报成功。系统设置与钢琴自身避让独立，不改变声音，工程生命周期见CR-001。

应用排除以应用标识为单位，不读取窗口文本。登录启动默认关闭，由用户主动启用。首版不强占全局快捷键；以后允许用户自定义总暂停快捷键并检测冲突。

## 05｜技术路线与总体架构

### 5.1 工程基线

建议 Swift＋AppKit＋SwiftUI。AppKit 负责非激活透明面板、窗口与系统事件，SwiftUI 负责设置与预览，琴键采用可独立变换的轻量图层。音频优先 `AVAudioEngine＋AVAudioUnitSampler`。这些是本项目选型，不是承诺某个 SDK 的全部行为已经验证。[S01][S02][S05]

首轮在开发者实际 Mac、当前可用 Xcode／SDK 上记录构建环境。部署目标暂建议 macOS 14 及以上、Apple Silicon 优先，M0 冻结最终支持矩阵；没有测试的系统或 Intel 不写入兼容声明。先做本地独立 App，商店分发与沙盒策略另行验证，既不预设必过也不预设不可行。

### 5.2 数据流

```text
InputMonitor → KeyStateReducer → MappingEngine → NoteCoordinator
                                             ├─ AudioEngine
                                             └─ PianoRenderer
PermissionController／ScenePolicy／DockAvoidance → 场景与安全状态
SettingsStore → 版本化配置；AssetRegistry → 已验收资源清单
```

| 模块 | 责任 | 不能做的事 |
|---|---|---|
| InputMonitor | 获取可观察事件、识别监听异常 | 吞事件、改字符、记逐键历史 |
| KeyStateReducer | 多键状态、双侧修饰键、重复过滤 | 由 UI 随机修正输入状态 |
| MappingEngine | PhysicalKeyID→MIDI 与标签 | 依据最终文字或哈希随机选音 |
| NoteCoordinator | 击发 ID、释放、重击、重置 | 让旧延迟释放误杀新音 |
| AudioEngine | 持续引擎、音源、混音与防削波 | 每次按键加载文件／重建播放器 |
| PianoRenderer | 音位几何、灰色标签、逐键状态 | 自己生成另一套音符事件 |
| DockAvoidance | 保守避让和恢复 | 与系统自动隐藏设置混为一谈、假装精确监听全部状态 |
| DockPreferenceController | 按用户偏好控制自动隐藏、读回及恢复 | 关闭未确认、失败报成功或修改其他系统偏好 |
| ScenePolicy | 权限、锁屏、排除、显示开关优先级 | 把只隐藏画面误当成静音 |

### 5.3 线程与资源原则

事件回调只做最小解析和入队，不进行磁盘、网络、音色载入或 UI 更新；输入状态归约在有序队列完成；音频控制按引擎要求序列化；界面操作回到主线程。音色预热后才进入正常发声状态。[S05]

不要让每次按键引发全界面重绘。静止时停止动画刷新；底部鼠标观察若采用采样，须低频、可休眠并测量开销，不用持续 120 Hz 轮询冒充实时性。

## 06｜代码实现规格

### 6.1 输入探针先行

优先验证 `CGEventTap` 的只观察路径与输入监控授权，分别处理 keyDown、keyUp、flagsChanged 及监听失效。Apple 的公开资料支持此路线，但授权缓存、签名和实际环境仍需要干净状态测试。[S01][S02][S03]

探针输出的是“测试用例是否通过”和聚合结果，不在真实工作期间持续记录 keyCode／时间序列。测试时使用预先规定的非敏感按键脚本；屏幕上的即时键状态只在测试页短暂显示。

64 项逐键检查、两侧修饰键交错、Fn／Caps Lock、自动重复、中文候选词、Command 快捷键、多键和丢失释放必须进入报告。若硬件无法识别某种多键组合，记录实际限制；64 音位或 64 声部不等于键盘有 64 键无冲。

### 6.2 音符生命周期

每次真实击发分配唯一 `pressID`，释放引用该 ID；尾音是声音策略，不反过来维持按键状态。旧释放必须先检查当前代次，不能把第二次击发关掉。

初版选定一个可验证的同音重击策略：例如同 MIDI 的新击发允许旧尾音被音源自然截断／交叉淡出，而不同音高可重叠。不得假设 AVAudioUnitSampler 按一个 pressID 就能独立控制同音的任意旧声部；抽象层的 ID 不会自动变成底层声部分配能力。

默认不使用永久 sustain pedal。普通钢琴长按也可以自然衰减，不要为了“按住”循环一段有接缝的音频。音源的 release 包络负责松开后的尾音；混响可以稍作补充，不将混响等同于踏板。

### 6.3 失败与恢复

监听器失效、锁屏、睡眠、权限撤回、引擎错误、映射切换时：停止新击发、清空按下集合、取消旧的延迟任务、停止持续声及混响尾音、重新评估状态。普通 10 秒长按不能仅因为超时被当成故障。

音源丢失时显示可理解的错误，可保留静音动画；不得悄悄换成刺耳提示音。资源未通过哈希／许可／格式检查，不进入正式资源清单。恢复音频设备时保留音量设置，不突然跳到满音量。

### 6.4 自动化测试与人工测试分离

纯逻辑单元测试覆盖归约器、映射、状态机、优先级及资源校验。渲染快照覆盖固定宽高与标签。音频离线测试覆盖覆盖范围、峰值及生命周期。真实输入、TCC 权限、Dock、内置扬声器延迟只能在真实环境补证；Linux 容器中的 JSON 校验不能当作 macOS 实测。

## 07｜音效设计与交付规格

### 7.1 声音目标

自然、柔和、轻量，能伴随长期打字；低音不轰鸣，高音不刺耳，快速输入不糊成一团。原音模式 64 个音高固定，普通键盘没有钢琴力度传感器，任何力度差异只能是预设或算法，不声称测到了真实击键力度。

建议初值：普通键 velocity 64、修饰键 48；主音量从保守增益开始；release 约 350—700 ms 的目标听感；混响轻微或关闭。最终以选定音源支持能力和用户试听为准；不能单靠任意延迟 note-off 宣称实现了可控 release。

### 7.2 资源路线

**优先路线 A：授权清楚的钢琴采样／音色库。** 音效对话寻找、试听、处理与整理，交付代码能加载的资源。VCSL 仓库将自身声明为 CC0，可作为候选；具体文件与来源仍需留证。[S10]

**候选路线 B：Salamander 等较大钢琴采样。** 该项目声明 CC BY 3.0，且当前仓库映射使用 SFZ／ARIA 扩展。可作为研究与试听来源，但不能把 `.sfz` 直接交给 Apple 的 SF2/DLS 载入方法，也不能以改扩展名代替转换。[S05][S11]

**备用路线 C：合成音。** 音效对话可以用代码生成调音准确的临时钢琴近似音，验证链路；未通过用户试听前，只标记“占位音”，不冒充真实采样。没有实际可用的音频生成工具时，不声称已调用生成服务。

最终资源格式在 M0 由代码和音效对话共同提案、主对话冻结。默认优先 SF2/DLS 音色库或已验证的采样器配置；WAV 源文件可以作为中间格式。SFZ 引擎／自研采样器属于路线变更，需评估依赖、授权、体积和开发成本，不能子对话自行引入。

### 7.3 音域、命名与处理

必须覆盖 MIDI 33—96，但不强制 64 份完全独立录音。允许多个根音采样经受控移调覆盖音域，要求区间、原始根音、移调量可追溯并逐音试听。音名八度可能与来源不同，不能只看文件名判断。

编辑中间格式建议 WAV、48 kHz、24-bit；最终格式以引擎／包体决策为准。单声道或立体声保持一致。裁掉起音前多余静音但不削去槌击瞬态；尾音淡出不应产生点击。禁止逐个音盲目拉到同样最大峰值，破坏自然音域响度关系。

命名示例 `piano_m060_v064_rr01.wav`，以 `m060` 为权威，不以 C4 字符串为权威。发布资源只保留需要的层数与音域；原始母带留在资源工作目录而不是全部塞进 App。

### 7.4 必须交付

`source_inventory.md`：原始来源、作者、版本／提交、取得日期、原始许可及修改记录。`audio.manifest.json`：引擎格式、覆盖音域、音色库参数、校验哈希和许可路径。`processing_recipe.md` 与处理脚本：可重复得到相同资源。`audition.wav`：逐音、字母输入、快捷键、快打和多音示例。`qa_audio.md`：音高、裁切、响度、尾音、爆音、加载、体积与内存结果。

试听序列使用合成测试事件，不抓取用户的真实输入。主对话请用户先从两种以内的候选音色中选择，不把十几个未经筛选的库直接甩给用户。

### 7.5 声部与音量安全

目标支持至少 64 个逻辑播放声部／尾音，分层采样可能消耗更多内部声部，必须测量，不能只填写一个参数。达到上限时优先回收低能量旧尾音，不任意切断刚击发的音。总线预留余量并做防削波；峰值与限制器参数是数字音频指标，不代表听力安全承诺。

内置／有线和蓝牙分开报告。蓝牙延迟不作为 App 相同的低延迟保证，不因蓝牙问题去修改用户的系统音频配置。

## 08｜UI 设计、贴图与动态效果

### 8.1 视觉方向

轻微立体的黑白琴键、薄底座、细分隔、克制的按压阴影。首版不做全屏光效、彩虹、粒子瀑布或大型钢琴外壳。声音背景化，画面也应背景化；标签默认开启且可由用户关闭，主题不能静默替用户关闭。

### 8.2 每个琴键底部的按键文字——硬性要求

以下适用于标签开启时；关闭仅隐藏文字层，琴键/映射/音频不变。**白键标签在白键自身最下方的可见面，黑键标签在黑键自身最下方的可见面。** 两种琴键不共用一条全局底部基线。标签跟随对应琴键整体下沉／回弹，不能漂在静止底座上。

| 项目 | 规范 |
|---|---|
| 内容来源 | 读取映射表的 displayLabel／labelParts；不手写第二份对应关系 |
| 颜色 | 白键用中深灰，如 #6B6B6B；黑键用浅灰，如 #C2C2C2 |
| 字号 | 初稿白键 10 pt、黑键 9.5 pt；一般不低于 9 pt，侧别角标单独处理 |
| 对齐 | 水平居中；白键离自身底边约 4 pt，黑键约 3 pt |
| 字体 | 使用系统可用字体；不随项目分发系统字体文件 |
| 内容 | 字母／数字／符号显示实体键本身，不能改成音名或中文输入结果 |
| 左右侧 | 两个 Command／Shift／Option 必须用小 L／R 或其他清楚标识区分 |
| 对比度 | 目标文字与所在键面的对比度至少 4.5:1；以实际画面测量，不凭灰色名称判断 |
| 缩放 | 先扩大宽度、使用紧凑符号和独立角标，不把整条位图缩小到文字看不清 |

长键名采用紧凑表示，如 Command 用 ⌘、Option 用 ⌥、Shift 用 ⇧、Control 用 ⌃、Return 用 ↵、Delete 用 ⌫；Space 可用 ␣，Fn 用 fn，方向键用箭头。左右角标作为独立小文字放在主符号旁边，不能把 `Command Right` 硬塞到十五个点宽的黑键里。字体缺字必须显式回退并测试；设置页展示完整中文名称。

标签动态绘制为独立文字层，**不烘焙进底图**。这样可以改映射、适配屏幕缩放、保持清晰并支持设置中的可访问说明。正常、按下、释放三种状态都必须可读，不能按下时闪成纯白导致文字消失。

### 8.3 默认尺寸与小屏适配

尺寸单位使用逻辑点 pt，而非原生像素或屏幕厘米。建议宽度公式为 `min(max(0.72 × screenWidth, 900), 1100, screenWidth − 48)`，默认总高 56 pt；上一版 52 pt 可保留为紧凑候选，由标签可读性决定。高度建议可调 48—76 pt。[S09]

白键横向空间等分为 38 份，黑键宽约白键 0.59 倍、高约白键 0.64 倍。1000 pt 的琴键区，白键约 26.3 pt、黑键约 15.5 pt；数字和单符号标签足够紧凑，但左右修饰键角标要特别验证。这只是几何计算，不是已经完成的可读性验收。

重点预览 900／1000／1100 pt 三个宽度，以及 1×／2× 缩放。在小于主支持宽度的窗口里，不允许挤压成不可读文字；可设置较宽浮层、提高标签排布密度或由主对话确定最小支持尺寸。

### 8.4 静态资源包

UI 对话交付可组合组件，不只交一张“好看的整条钢琴”。推荐组件：白键静态面、白键按压面、黑键静态面、黑键按压面、底座、柔和阴影和可选尾音光层；也可用矢量与程序参数替代重复 PNG。

参考母版：白键 32×64 pt、黑键 19×41 pt；分别提供 1×／2× 透明 PNG 或经验证可用的矢量资源。实际运行按主题几何缩放，母版只是资源设计坐标。阴影额外边界、切片区域、锚点和透明通道必须写进清单。

白键按音位需要不同遮挡轮廓，可用程序蒙版和裁剪组合；不能把黑键缝隙烤进白键贴图，导致 E—F／B—C 处出现假黑键。不要为每个音符复制一套无法维护的贴图，除非特殊形状确有需要。

所有资源不含文字、真实 Dock 图标、壁纸或背景桌面。整条钢琴合成图只作预览，不是运行时交付的唯一资源。AI 生成图可用于概念探索和材质参考；最终按键几何、透明边缘和标签必须确定性重建，不能靠生成图猜测 64 个琴键数量。

### 8.5 动画状态

| 状态 | 视觉行为 | 初始参数 |
|---|---|---|
| Rest | 原位置与阴影 | 静止不持续刷新 |
| Pressing | 下沉并收短投影 | 35—50 ms |
| Held | 保持按下 | 不自行回弹、不重复闪烁 |
| Releasing | 回到原位 | 80—120 ms |
| Residual | 可选低强度尾音光 | 200—400 ms，默认可关闭 |
| Hidden | 面板整体隐藏 | 不积压动画事件 |

白键下沉约 1.5—2.5 pt，黑键约 1—2 pt，参数待原型。非常短的敲击可设置约 45 ms 的视觉可见下限，但不能延后音频，也不能延后真实状态归约；快速重击应从当前变换继续，避免堆积多个延迟回弹任务。

减少动态效果开启时，使用即时轻微明暗变化，不再做明显位移。图层顺序依次是底座、白键及白键文字、黑键及黑键文字、克制的效果；效果不能遮住标签。音高越大横坐标越靠右。

### 8.6 UI 对话交付边界

必须交：UI 规范、逐键资源／矢量、主题 JSON、动画参数、九种以上尺寸／状态预览、透明资源说明、标签对比度与溢出检查、图形来源声明。可额外交独立可运行预览或 SwiftUI 组件示例，但不修改生产工程的窗口、输入、音频和 `.xcodeproj`；这些由代码对话集成。

浮层默认鼠标穿透，不要求悬停才显示标签，也不在底部放难以操作的控制按钮。鼠标试听和映射查看放在设置预览里。[S07]

## 09｜Dock、窗口与多屏策略

### 9.1 实现边界

用独立透明、非激活面板实现钢琴，不注入或重绘系统 Dock。用户已确认程序可控制系统Dock自动隐藏，默认开启，可关闭并先提示重叠风险。`NSDockTile` 针对应用自己的 Dock 内容，不是整个 Dock 背景的替换接口。`NSScreen.visibleFrame` 反映可用区域，但自动隐藏时仍可能预留边界，因此不能当作“Dock 已收起”的可靠逐帧信号。[S06][S08]

**P0 实现“智能避让”；“所有情况下精确同步”只有实测通过才能命名。** 鼠标远离屏幕边缘不等于已经确认 Dock 收回。尤其键盘呼出、菜单保持展开与拖拽要单独测试。

### 9.2 状态优先级

先处理总暂停／权限或系统阻断，再处理应用排除，再处理用户关闭视觉，然后处理 Dock 避让／全屏策略，最后才允许显示。多个原因可以同时存在，移除一个原因不能错误覆盖其他隐藏原因。

进入底部安全区域时，立即开始约 80—120 ms 淡出；退出更大的恢复区域并稳定 300—500 ms 后恢复。两个区域形成迟滞，避免鼠标在边界附近导致闪烁。拖拽期间保持隐藏。没有可靠菜单状态时选择保守隐藏，并将限制写入报告。

### 9.3 降级与权限

Dock 常显时可将钢琴放在 Dock 上方或用户选定位置；Dock 在左右时，钢琴仍可放底部，但单独验证交互。自动隐藏设置的读写、退出恢复与外部变化由独立控制器处理，路径及刷新方式须验证；只控制用户选择的自动隐藏，不改位置、大小或其他Dock偏好。开发测试不自动写当前用户系统设置。

窗口层级不得遮住锁屏、权限弹窗、系统菜单和 Dock，不使用屏保级窗口强压系统。全屏、Mission Control、Stage Manager、Space 切换先采用保守隐藏或明确的用户选择。默认只显示一条钢琴，优先内置屏；拔掉目标屏后回到有效显示器，不在屏外残留窗口。

增强型 Dock 识别若确需辅助功能权限，必须另写 ADR 并经用户批准。基本模式不应先索取屏幕录制、麦克风、完全磁盘访问或管理员权限。

## 10｜统一接口与数据契约

正式契约见 `docs/01_Interface_Contract.md` 与 `contracts/`。以下约束优先于任何子对话自己的临时代码。

| 数据对象 | 必需字段／语义 |
|---|---|
| PhysicalKeyID | 稳定英文 ID，如 keyA、commandLeft；不使用输入后的字符作为身份 |
| KeyMapping | schemaVersion、mappingVersion、layout、physicalKeyID、MIDI、displayLabel、labelParts、row |
| NormalizedKeyEvent | eventID、keyID、down／up／pulse、单调时钟时间、捕获能力状态；仅在内存流转 |
| NoteEvent | pressID、keyID、MIDI、velocity、down／release／panic、mappingVersion |
| KeyVisualState | MIDI、activePressIDs、pressed、animationGeneration；标签来自映射 |
| AudioManifest | artifactState、format、noteRange、音色库参数／采样区、来源许可、哈希、QA 报告 |
| UITheme | artifactState、尺寸、颜色、字体策略、标签规则、动画与资源切片说明 |

版本含义：schemaVersion 改的是结构；mappingVersion 改的是按键到音符；themeVersion 和 audioPackVersion 改的是资源。修改字段名、音域或单位必须先提接口变更，不能在交付时让其他对话自行猜。

模板必须写 `artifactState: template`；正式资源写 `ready` 前，要验证文件存在、哈希匹配、音域完整、许可完整、引擎可加载。加载器不得把模板或演示路径误当正式资产。

## 11｜性能、隐私与安全

### 11.1 暂定性能目标

| 指标 | 初步目标 | 测量说明 |
|---|---|---|
| 内部事件到音频提交 | P95 不高于 10 ms | 使用同一单调时钟；不是扬声器出声延迟 |
| 内置／有线端到端 | 争取 P95 不高于 30 ms | 需独立环回／声学测量；没有仪器标未测 |
| 动画首次可见 | 一般在一到两帧内 | 记录刷新率与测试方法 |
| 空闲 CPU | 目标低于单核 1% | 固定机器测 5 分钟，不作跨机型承诺 |
| 常规打字 CPU | 目标平均低于单核 5% | 记录音源、效果、每秒事件数 |
| 内存 | 初步预算不高于 250 MB | 资源路线冻结后复核，不牺牲稳定性硬凑 |
| 安装包资源 | 初步争取不高于 150 MB | 超出说明质量／体积取舍 |
| 连续工作 | 60 分钟无卡键、无崩溃、无持续增长 | 合成事件＋人工真实使用分别验收 |

以上都是工程目标，不是已测数据；M0 之后可以带证据调整。短时 CPU 峰值、音源预加载时内存与稳态数据分开报告。不要用主观“感觉很顺”代替数值，也不要把声音回调时间当声学延迟。

### 11.2 数据最小化

只处理必要的实体键身份和瞬时状态，不读取／拼接文本，不读取剪贴板，不持久化真实逐键序列、逐键时间、应用与按键的关联记录，不上传数据。错误日志只记错误码、版本和聚合指标，不能夹带用户输入。

性能分析使用合成脚本或不含键身份的聚合统计。截图与录屏用虚构测试文本，不能把聊天、密码、业务资料带入验收包。代码、音频、UI 三个对话均遵守相同规则。

### 11.3 系统保护与旁路泄露

安全输入用于限制其他进程截获敏感键盘事件。遵守系统阻断，不尝试关闭别的应用启用的安全输入；归档文档提供机制背景，当前兼容性仍须验证。[S04]

不能宣传“百分之百知道所有密码框”。用户可使用应用排除和总暂停。固定音高与按键标签本身会向旁听、录音和共享屏幕透露按键，因此敏感输入和屏幕共享时应关闭声音及画面。离线不等于没有这种泄露风险。

## 12｜资源生产、来源与发布规范

### 12.1 音效与 UI 都必须可追溯

第三方资源逐项记来源、作者、许可原文、具体版本／提交、下载时间、修改说明、校验值和署名方式。开源代码许可不能替代音源或贴图许可；音乐作品的播放授权也不自动等于允许把单音采样打包分发。

免费不是充分证据；不能从商业钢琴 App、GarageBand、商业音源插件中擅自提取采样。候选库可下载评估，但正式加入发布包前，检查所取文件对应的实际许可与附带条件；本文件不是对所有候选素材的法律结论。

### 12.2 资源目录建议

```text
Resources/Audio/<pack-version>/      # 已批准的运行时资源
Resources/UI/<theme-version>/        # 已批准的图形组件与参数
Design/Audio/                       # 原始记录、处理配方、试听、QA
Design/UI/                          # 源文件、预览、动效说明、QA
Licenses/                           # 实际使用资源的许可与署名
```

音效对话与 UI 对话只提交自身负责的资源和文档；资源注册、构建设置、App Bundle 路径及运行时加载由代码对话统一集成。大文件先提出体积计划；不在未获同意时批量下载数 GB 音源或提交无关源库。

### 12.3 发布前检查

固定 Bundle ID 和签名策略，独立分发的签名／公证／安装权限回归由代码对话执行，主对话批准。没有证书或开发者账号时，交本地测试构建并说明差异，不能假称完成公证。自动更新、商业购买、发布到商店或公网均需明确授权。

## 13｜四个对话的组织与权限

### 13.1 组织图

```text
吴铭 ⇄ ① 项目主对话：目标、方向、排期、任务、验收
             ├─ ② 代码实现：App、逻辑、引擎、集成、测试
             ├─ ③ 音效实现：音源、处理、许可、试听、资源包
             └─ ④ UI 实现：视觉、贴图、标签、动效、预览
```

四个对话是独立工作上下文，不是默认能互相读取的聊天室。通过共享仓库中的任务卡／交接文件，或用户转发交接内容衔接；没有实际通信工具时不能声称已向另一个对话发消息、已获得其确认。

### 13.2 ① 项目主对话

唯一面向用户的总负责人。维护需求、主文档、任务板、决策日志、风险与版本；收敛分歧；安排任务与验收；控制范围；每阶段报告“已完成、证据、未解决、下一步”。可以管理文档和授权集成，不取代其他对话长期编写实现或制作资源。

只有主对话可以批准改变音域／映射原则、UI 硬要求、权限范围、依赖、平台范围和里程碑。涉及用户明确目标的变更必须问用户；纯工程内部调整可以有证据地裁决并记录。

### 13.3 ② 代码实现对话

负责唯一的生产工程：输入、状态、映射、音频播放、窗口、动画接入、设置、权限、资源加载、测试、构建与打包。音效对话制作声音，代码对话实现播放它的程序；UI 对话制作样式与动效规格，代码对话实现最终运行时渲染。

可写生产源码、工程设置、单元测试、构建脚本及指定交接文档。不能擅改主需求，不自行挑选最终音色，不为了省事删除标签功能、静音修饰键、增加无关权限；用户主动关闭标签是合法偏好。临时占位声／图必须清楚标记，后续替换不应重写结构。

### 13.4 ③ 音效实现对话

负责寻找或生成音源、授权检查、下载、编辑、转换、裁切、调音、响度匹配、音源包、试听和质量报告；必要的处理脚本放在专属目录。需与代码对话对齐引擎格式，但不直接改输入监听、生产音频引擎或 Xcode 工程。

不能只给链接或一段“建议用这个”的描述。最终必须交实际可用资源及可重现的处理说明。下载或生成能力受限时，明确未完成项，不假造资源存在。

### 13.5 ④ UI 实现对话

负责整体视觉规范、可组合静态贴图／矢量、灰色按键标签排布、按下／回弹／尾音特效、尺寸适配、设置预览与交接。可制作独立预览代码，不动生产系统接入。

不能只交一张不可拆分的整图；不能把文字烘焙在纹理中；不能为效果牺牲真实黑白键数量；不能把所有黑键标签挤到全局底部；不能把“仅显示音名”当作“显示对应按键”。

## 14｜仓库、任务与交接规则

### 14.1 单一事实来源

以仓库中已批准的文档与契约为准，不以某个子对话的一句临时建议覆盖全局。优先级为：用户最新明确决定 → 主对话记录的 ADR → 已冻结契约与主文档 → 当前任务卡 → 临时讨论。遇到冲突先停止相关变更，其他独立工作可以继续。

根目录 `AGENTS.md` 只保留短规则和文档索引；完整规格放 `docs/`。OpenAI 官方资料将 AGENTS.md 作为可用的持续仓库指引，并支持通过计划文件保留进度；本项目其余文件名都是我们的协作约定，不是工具强制要求。[S12]

### 14.2 并行隔离

推荐三个执行对话分别使用 Git 分支／独立 worktree，从同一个批准基线开始。主对话不要求三个对话在同一个工作目录同时改文件。官方资料也把 worktree 用于隔离并行运行；具体创建与合并以当前可用工具和实际仓库状态为准。[S13]

建议分支 `work/code`、`work/audio`、`work/ui`，集成分支由主对话协调。生产工程文件由代码对话唯一维护；音效与 UI 各自只写专属目录。主对话批准后由代码对话集成资源提交，主对话核对验收证据。

不使用破坏性 reset、强推或覆盖别人的未提交改动来解决冲突。开始前确认基线提交、工作树状态和可写路径；没有仓库时先做初始化提案，不假设它已经存在。

### 14.3 每张任务卡必须含有

任务 ID、归属对话、基线提交、输入文档／资源版本、目标、允许修改路径、禁止范围、交付物、验收项、依赖、风险和回滚方案。依赖分成“必须先有”和“可用占位并行”两类，避免音效等代码、代码等 UI 的循环等待。

### 14.4 每轮交接必须含有

实际完成与未完成、变更文件、资源／提交哈希、复现步骤、测试环境、通过／失败／未测、运行截图或音频示例路径、已知限制、需要谁处理什么。不能写“已完成”却无文件；不能用 AI 的推测代替用户实机反馈。

主对话收到交接后，先核对证据与契约，再决定接收、退回或附条件接收。每次接收更新任务板；只有主对话可以把里程碑标为完成。

## 15｜项目阶段、依赖与首轮任务

### M0：验证与契约冻结

主对话建立任务板、决策日志及环境记录，发出 C-001、A-001、U-001。代码完成输入／窗口／音频三个探针；音效提出最多两个许可明确的候选及小样；UI 完成带灰色标签的 64 键规格与尺寸预览。

出口条件：实际捕获能力有记录；Dock 可行行为与边界明确；至少一种音源路线能被加载；标签在主支持宽度可读；所有接口版本统一。Fn 或完整 Dock 同步无法达到目标时，必须将降级方案交用户确认，不能默默少做。

### M1：最小闭环

形成可运行 App：精简菜单栏主入口、标签开关、系统Dock自动隐藏及关闭提醒、权限引导、下方五排事件、固定映射、采样声音、多音、64 键可视化与灰色标签、Dock 避让、菜单栏、总暂停。资源可先用已标注占位，音画必须同源。

出口条件：普通工作输入不受影响、核心快捷键正确、琴键数量与映射一致、暂停真正停止声音与监听。至少交一个真实 Mac 录屏／演示与构建说明。

### M2：资源定稿与日常可用

接入批准音色和 UI，用户试听映射与音色；完善特殊键、设备切换、排除应用、睡眠锁屏、尺寸与低功耗。检查 60 分钟工作测试，完成 P0 验收矩阵。

出口条件：无阻断性缺陷；占位素材已替换或明确保留为测试版；许可完整；性能与兼容限制有真实记录。

### M3：测试版交付与稳定性

修复试用反馈，调整音色／动效，处理跨显示器、缩放与 Dock 边界。任何新功能都作为变更，不挤占核心缺陷修复。每次升级回归权限、映射迁移和资源版本。

### M4：分发准备

经用户授权后完成签名、公证与安装包，提供隐私说明、第三方署名和版本说明。缺少发布条件时停在本地测试版，不阻塞已完成的功能验收。

### 首轮并行任务表

| 任务 | 负责 | 内容 | 先决条件／交付 |
|---|---|---|---|
| PM-001 | 主对话 | 建立基线、版本与任务卡 | 文档已读；输出首轮任务，不提前扩功能 |
| C-001 | 代码 | 三探针＋测试环境＋64 键能力表 | 可用 Mac；资源可用最小占位 |
| A-001 | 音效 | 两个候选、来源许可、小样、加载格式提案 | 读取音域契约；不要下载整个庞大库 |
| U-001 | UI | 64 键几何、底部灰标签、三宽度预览、动效规格 | 用固定映射和模拟事件，不等音频完成 |
| PM-002 | 主对话 | 评审三份报告并冻结 M1 路线 | C／A／U 实际证据；必要时请用户决策 |

开发进度按出口条件推进，而不是按某个对话“说完成了”推进。本版不承诺固定天数；M0 之后根据实测困难、资源与用户反馈再排期。

## 16｜验收矩阵与完成定义

完整可勾选清单见 `docs/02_Acceptance.md`，初始均为“未测试”。核心测试至少包括以下组别。

| 组别 | 测试内容 | 通过条件 |
|---|---|---|
| K 数量 | 64 输入、MIDI33—96、38白26黑 | 无遗漏、无重复、标签与映射一致 |
| I 输入 | 中英文、候选词、标点、删除、重复 | 原应用结果和未开启时一致 |
| M 组合 | 左右修饰、Command+C/V、Shift+字母 | 每实体按下只击发一次，独立释放 |
| N 生命周期 | 快速重击、丢失释放、长按 | 无旧释放杀新音、无卡键长鸣 |
| A 声音 | 逐音、多音、快打、尾音、设备切换 | 无坏采样、明显爆音和失控堆积 |
| U 图形 | 64键几何、标签开启/关闭、按压与回弹 | 黑键标签在自身底部、不溢出、不模糊 |
| D Dock | 鼠标／键盘呼出、菜单、拖拽、常显、左右 | 不挡操作；不支持情况有批准降级 |
| S 场景 | 锁屏、睡眠、权限变化、安全输入、排除 | 安全停用，恢复无旧状态 |
| P 性能 | 空闲、常规打字、压力、60分钟 | 给出真实指标和机器条件 |
| L 来源 | 音源、UI、代码依赖与署名 | 文件、版本、许可对应，发布无占位 |

每项状态只能是未测试、通过、失败、受限通过／用户批准降级。编译成功不能替代这些组别全部通过。主对话验收时要求代码、资源、测试证据三者版本一致。

正式“完成”的定义：用户目标达成；P0 全部通过或有用户明确批准的例外；资源许可与包体完整；可重复构建；安装与使用说明可操作；没有隐藏的逐键日志；没有把技术限制包装成已实现功能。

## 17｜风险、决策与变更

| 风险 | 影响 | 处理办法 |
|---|---|---|
| Fn／Caps Lock 事件不完整 | 64输入不等于64可靠事件 | M0 独立验证；保留音位，限制透明，降级请用户确认 |
| Dock 无可靠完整状态 | 钢琴恢复时可能与 Dock 重叠 | 优先操作安全；保守避让；必要时增强或手动模式 |
| 64音跨度与随机打字不悦耳 | 长期开启意愿下降 | 柔和音色、固定可试听映射、受控尾音；不暗改音 |
| 黑键标签太窄 | 小屏无法识别 | 紧凑符号＋侧别角标、最低字号、实际缩放验收 |
| 音源过大／格式不支持 | 内存、包体或集成失败 | 先试小样；格式冻结；转换可复现，不改后缀假装兼容 |
| 多对话改同一文件 | 冲突与隐性接口漂移 | 专属目录、worktree、接口版本、唯一工程集成人 |
| 密码／共享屏幕泄露 | 声音与标签暴露输入 | 系统保护、排除、总暂停、明确说明 |
| 测试环境不足 | 兼容性被高估 | 缺少机器就标未测试，不以模拟结果充当实测 |

决策文件初始标明“已明确”“本版建议”“待验证”，不把用户没有批准的选择写成其个人决定。需要更改时填写问题、选项、证据、影响、决定者和回滚。新需求优先入待办，不由任何子对话随手扩展首版。

## 18｜启动与使用本开发包

把整个开发包放进新的专用项目目录，避免在通用下载目录直接开启编程代理。先开“项目主对话”，提供主文档、`AGENTS.md` 与对应启动说明；让它建立首轮任务，再分别打开代码、音效和 UI 对话，将各自启动说明及任务卡交给它们。

有共享仓库时以文件路径和提交交接；只有聊天窗口时上传主文档、契约与对应启动说明，再把各执行对话的交接摘要转发主对话。用户只需要对产品取舍、声音和视觉效果作决定，不必替三个执行对话协调文件命名与接口。

本交付不包含真实生成／下载的钢琴采样，不包含最终琴键贴图，不包含可运行 App；这些是后续三个执行对话的任务。它包含完整开发规划、可粘贴启动说明、任务／交接模板、64键映射初稿和可校验契约，供项目直接进入 M0。
